# แผนงานแอปร้องเพลงบนเว็บไซต์

**วันที่จัดทำ:** 27 ตุลาคม 2026  
**เป้าหมาย:** เว็บคาราโอเกะที่ผู้เล่นค้นหาเพลงจาก YouTube เพิ่มเพลงเข้าคิว ร้องพร้อมวิดีโอเต็มจอ รับคะแนนจากเสียง และส่งภาพขึ้นทีวีได้ในเฟสสุดท้าย

## ภาพรวมประสบการณ์

1. ผู้ใช้สร้างห้อง แล้วแชร์ลิงก์หรือรหัสห้องให้เพื่อน
2. ผู้เล่นค้นหาเพลงใน YouTube จากชื่อเพลงหรือศิลปิน เลือกผลลัพธ์ แล้วกดเพิ่มเข้าคิว
3. โฮสต์เริ่มเพลง วิดีโอเล่นเต็มจอ และทุกคนเห็นสถานะเพลงกับคิวเดียวกัน
4. หลังเพลงจบ ระบบแสดงคะแนนเสียงร้อง แล้วเปิดโอกาสให้จัดคิวเพลงถัดไป
5. ในเฟสสุดท้าย ผู้ใช้เชื่อมต่อทีวีที่รองรับ Cast โดยมือถือหรือคอมพิวเตอร์ทำหน้าที่ควบคุมห้อง

## ผู้ใช้และสิทธิ์

| บทบาท | สิ่งที่ทำได้ |
|---|---|
| โฮสต์ | สร้างห้อง เริ่ม/ข้ามเพลง จัดลำดับคิว ลบเพลง และปิดห้อง |
| ผู้ร่วมเล่น | ค้นหาเพลง เพิ่มเพลง ดูคิว และให้คะแนนผู้ร้องตามสิทธิ์ของห้อง |
| หน้าจอทีวี | แสดงเพลงที่กำลังเล่น ชื่อผู้ร้อง คะแนน และเพลงถัดไป โดยรับสถานะจากห้อง |

## แผนงานเป็นเฟส

### เฟส 0 — ตรวจสอบความเป็นไปได้และขอบเขต

**เป้าหมาย:** ยืนยันข้อจำกัดของ YouTube, ระบบคิดคะแนน และเส้นทาง Cast ก่อนเริ่มพัฒนาฟีเจอร์เต็มรูปแบบ

- ทดลองค้นหาวิดีโอด้วย YouTube Data API และเพิ่มผลลัพธ์เข้ารายการทดลอง
- ทดลองเล่นวิดีโอผ่าน YouTube IFrame Player API แบบเต็มจอ และตรวจจับสถานะเพลงจบ
- ทดสอบวิดีโอที่อนุญาตและไม่อนุญาตให้ฝังในเว็บ
- ทดลอง Cast จากอุปกรณ์เป้าหมาย พร้อมบันทึกว่าอุปกรณ์ใดส่งภาพ/เสียงได้ และมีข้อจำกัดใด
- เลือกเพลงตัวอย่างที่มีข้อมูลโน้ตและจังหวะอ้างอิงสำหรับระบบคะแนน
- ระบุเบราว์เซอร์และทีวีเป้าหมายของรุ่นแรก

**ผลส่งมอบ:** บันทึกผลต้นแบบ, รายการอุปกรณ์ที่รองรับ, รูปแบบข้อมูลเพลงสำหรับคะแนน และขอบเขต MVP

**เกณฑ์ผ่าน:** เล่นวิดีโอที่ฝังได้จนจบ, ตรวจจับจบเพลงได้, ค้นหาและเลือกผลลัพธ์ได้ และมีเส้นทาง Cast ที่ทดสอบได้อย่างน้อยหนึ่งแบบ

### เฟส 1 — ห้องร้องเพลงและบัญชีผู้เล่นแบบเบา

**เป้าหมาย:** ให้ผู้ใช้สร้างห้องและเข้าร่วมได้โดยไม่ต้องตั้งค่าซับซ้อน

- สร้างห้องด้วยรหัสสั้นและลิงก์เชิญ หรือ QR code
- เข้าร่วมห้องด้วยชื่อเล่น
- กำหนดผู้สร้างห้องเป็นโฮสต์ และให้โฮสต์โอนสิทธิ์ได้
- แสดงรายชื่อผู้เข้าร่วม สถานะห้อง และผู้ร้องคนปัจจุบัน
- ซิงก์สถานะห้องให้ผู้เข้าร่วมเห็นตรงกันแบบใกล้เคียงเรียลไทม์
- รองรับการกลับเข้าห้องหลังรีเฟรชหรือขาดการเชื่อมต่อชั่วคราว

**เกณฑ์ผ่าน:** ผู้ใช้หลายคนเข้าห้องเดียวกันได้ เห็นรายชื่อและสถานะตรงกัน และโฮสต์ควบคุมห้องได้

### เฟส 2 — ค้นหาเพลง YouTube และจัดการคิว

**เป้าหมาย:** ค้นหาและเพิ่มเพลงจากในเว็บได้โดยตรง

- ช่องค้นหาด้วยชื่อเพลง ศิลปิน หรือคำค้นทั่วไป
- แสดงภาพปก ชื่อวิดีโอ ช่อง ระยะเวลา และสถานะว่าเล่นแบบฝังได้หรือไม่
- มีปุ่ม **เพิ่มเข้าคิว** ในแต่ละผลค้นหา
- ใช้ YouTube Data API สำหรับผลค้นหา และตรวจสอบความพร้อมเล่นก่อนเพิ่ม
- แสดงคิวปัจจุบัน ผู้ขอเพลง และลำดับเพลงถัดไป
- ให้โฮสต์เลื่อน ลบ หรือข้ามเพลงได้
- ป้องกันการเพิ่มวิดีโอซ้ำในคิวเดียวกัน และกำหนดจำนวนเพลงต่อคนได้
- แสดงข้อความเมื่อวิดีโอถูกลบ เป็นส่วนตัว หรือไม่อนุญาตให้เล่นแบบฝัง
- จำกัดการค้นหาถี่เกินไปและทำ pagination เพื่อควบคุมโควตา API

**เกณฑ์ผ่าน:** ค้นหาเพลง เลือกผลลัพธ์ เพิ่มเข้าคิว และให้ผู้ร่วมเล่นทุกคนเห็นการเปลี่ยนแปลงได้

### เฟส 3 — เล่นเพลงเต็มจอและเปลี่ยนเพลงตามคิว

**เป้าหมาย:** ทำให้การร้องเพลงและการต่อเพลงถัดไปมีลำดับชัดเจน

- เล่นวิดีโอผ่าน YouTube IFrame Player API
- มีหน้ารอเพลง หน้ากำลังเล่น และหน้ารอคะแนน
- เล่นวิดีโอเต็มจอ โดยไม่บังส่วนควบคุมหรือองค์ประกอบของ YouTube Player
- แสดงชื่อผู้ร้องและเพลงถัดไปในพื้นที่ของเว็บที่ไม่ทับตัวเล่น
- ตรวจจับสถานะเล่น หยุด และจบเพลง เพื่ออัปเดตสถานะห้อง
- เมื่อเพลงจบ ให้หยุดที่หน้าคะแนนก่อนเริ่มเพลงถัดไป
- หากเริ่มเล่นอัตโนมัติไม่ได้ ให้แสดงปุ่มแตะเพื่อเริ่ม
- รองรับโฮสต์ข้ามเพลงและแจ้งเหตุผลเมื่อวิดีโอเล่นไม่ได้

**เกณฑ์ผ่าน:** เพลงเล่นเต็มจอ จบแล้วเข้าสู่หน้าคะแนน และคิวพร้อมสำหรับเพลงถัดไป โดยอุปกรณ์ในห้องเห็นเพลงปัจจุบันตรงกัน

### เฟส 4 — ให้คะแนนจากไมโครโฟน

**เป้าหมาย:** วัดความแม่นของการร้องโดยอาศัยเสียงผู้ร้องและข้อมูลอ้างอิงของเพลง

- ขออนุญาตใช้ไมโครโฟนก่อนเริ่มร้อง และมีขั้นตอนทดสอบระดับเสียง
- มีช่วงปรับเทียบไมโครโฟนและตรวจเสียงรบกวนจากลำโพง
- วิเคราะห์ความตรงของระดับเสียงและจังหวะ เทียบกับข้อมูลโน้ต/เวลาอ้างอิงของเพลง
- แสดงคะแนนรวมและรายละเอียด เช่น ความตรงของโน้ตกับจังหวะ
- จัดทำรายการเพลงที่รองรับคะแนนอัตโนมัติ และระบุเพลงที่ไม่มีข้อมูลอ้างอิง
- สำหรับเพลงที่ยังไม่มีข้อมูล ให้เล่นได้ตามปกติและใช้คะแนนโหวตจากผู้ฟังแทน
- ประมวลผลเสียงระหว่างร้องโดยไม่บันทึกเสียงต้นฉบับเป็นค่าเริ่มต้น

**เกณฑ์ผ่าน:** เพลงที่รองรับแสดงคะแนนหลังจบเพลงได้ คะแนนและรายละเอียดอ่านเข้าใจง่าย และผู้ใช้ควบคุมการอนุญาตไมโครโฟนได้

### เฟส 5 — ความเสถียร ความเป็นส่วนตัว และทดสอบกับผู้ใช้

**เป้าหมาย:** เตรียมระบบให้ใช้งานในห้องจริงได้ต่อเนื่อง

- จัดการกรณีอินเทอร์เน็ตหลุด รีเฟรชหน้า โฮสต์ออกจากห้อง หรือ Cast หลุด
- ให้สถานะห้องและคิวกลับมาตรงกันหลังเชื่อมต่อใหม่
- เพิ่มการรายงานเพลงผิดพลาด การควบคุมสแปม และการลบผู้ใช้รบกวนโดยโฮสต์
- อธิบายการใช้ไมโครโฟนก่อนขอสิทธิ์ และเปิด/ปิดไมค์ได้ชัดเจน
- เก็บเฉพาะข้อมูลจำเป็น เช่น คะแนนและประวัติห้องตามนโยบายที่กำหนด
- ทดสอบบนมือถือ แท็บเล็ต และเดสก์ท็อป รวมถึงการใช้งานผ่านคีย์บอร์ด
- ทดลองห้องขนาดเล็กและปรับประสบการณ์จากข้อเสนอแนะ

**เกณฑ์ผ่าน:** ผู้ใช้เข้าใจสถานะไมค์ ระบบฟื้นจากการหลุดชั่วคราวได้ และโฮสต์จัดการห้องได้โดยไม่ต้องปิดห้องใหม่

### เฟส 6 — Cast ขึ้นทีวี

**เป้าหมาย:** ให้ทีวีแสดงการร้องเพลงเต็มจอ ขณะที่มือถือหรือคอมพิวเตอร์ใช้ควบคุมห้อง

- เพิ่มปุ่ม Cast และแสดงสถานะการเชื่อมต่อ
- ส่งเพลงปัจจุบันและสถานะคิวไปยังทีวีที่รองรับ
- ออกแบบหน้าจอทีวีให้อ่านได้จากระยะไกล: เพลง ผู้ร้อง คะแนน และเพลงถัดไป
- คงการควบคุมคิวและปุ่มข้ามเพลงไว้บนอุปกรณ์ผู้ส่ง
- ซิงก์ตำแหน่งเล่นและสถานะเพลงระหว่างผู้ส่งกับทีวี
- รองรับการเชื่อมต่อใหม่เมื่อผู้ส่งหรือทีวีหลุดชั่วคราว
- ทดสอบเสียงจากทีวีกับไมโครโฟนที่ใช้คิดคะแนน
- รุ่นแรกให้ความสำคัญกับ Chromecast และทีวีที่รองรับ Google Cast; เพิ่ม AirPlay หรือระบบทีวีอื่นเป็นขอบเขตแยก

**เกณฑ์ผ่าน:** ผู้ใช้เชื่อมต่อทีวีที่รองรับได้ วิดีโอและเสียงเล่นบนทีวี มือถือควบคุมคิวได้ และระบบกลับมาทำงานได้หลังหลุดชั่วคราว

## หน้าจอหลักที่ควรมี

1. **หน้าสร้าง/เข้าห้อง:** สร้างห้อง ใส่รหัส หรือเปิดลิงก์เชิญ
2. **หน้าห้องและคิว:** รายชื่อผู้เล่น คิวเพลง ช่องค้นหา และการควบคุมของโฮสต์
3. **หน้าค้นหา:** ผลค้นหา YouTube พร้อมข้อมูลวิดีโอและปุ่มเพิ่มเข้าคิว
4. **หน้าเล่นเพลง:** YouTube Player เต็มจอ พร้อมข้อมูลผู้ร้องและเพลงถัดไป
5. **หน้าคะแนน:** คะแนนเสียงร้อง คะแนนโหวต และปุ่มไปเพลงถัดไป
6. **หน้าควบคุม Cast:** เชื่อมต่อ/ตัดการเชื่อมต่อทีวีและควบคุมการเล่น

## แนวทางข้อมูลและระบบ

| ข้อมูล | รายละเอียดสำคัญ |
|---|---|
| ห้อง | รหัสห้อง โฮสต์ สถานะ และเพลงที่กำลังเล่น |
| ผู้เล่น | ชื่อเล่น สิทธิ์ และเวลาที่เข้าห้อง |
| เพลง | YouTube video ID ชื่อ ช่อง ระยะเวลา และสถานะการฝัง |
| รายการคิว | ห้อง เพลง ผู้ขอ ลำดับ และสถานะ |
| ข้อมูลอ้างอิงเพลง | จุดเวลาและระดับเสียงเป้าหมายสำหรับเพลงที่คิดคะแนนได้ |
| คะแนน | ผู้ร้อง เพลง คะแนนรวม รายละเอียด และเวลาที่ร้อง |

ให้เซิร์ฟเวอร์เป็นแหล่งข้อมูลหลักของสถานะห้องและคิว ส่วนหน้าจอแต่ละเครื่องรับการเปลี่ยนแปลงแบบเรียลไทม์ การค้นหาใช้ YouTube Data API และการเล่นใช้ YouTube IFrame Player API การวิเคราะห์เสียงใช้สัญญาณจากไมโครโฟนที่ผู้ใช้อนุญาต

## ความเสี่ยงและแนวทางรับมือ

| ความเสี่ยง | แนวทางในแผน |
|---|---|
| วิดีโอบางรายการฝังในเว็บไม่ได้หรือถูกลบ | กรอง/ตรวจสถานะก่อนเพิ่ม และแจ้งผู้ใช้เมื่อเล่นไม่ได้ |
| เพลงทั่วไปไม่มีโน้ตอ้างอิงสำหรับคิดคะแนน | เริ่มจากคลังเพลงที่เตรียมข้อมูลแล้ว และใช้โหวตแทนเมื่อไม่มีข้อมูล |
| เสียงเพลงจากทีวีเข้ามาในไมโครโฟน | ทดสอบตำแหน่งไมค์ เสียงรบกวน และวิธีปรับเทียบก่อนรับรองคะแนน |
| การ Cast ต่างกันตามอุปกรณ์และเบราว์เซอร์ | ทำต้นแบบตั้งแต่เฟส 0 และระบุรุ่นอุปกรณ์ที่รองรับอย่างชัดเจน |
| โควตาการค้นหาถูกใช้มากเกินไป | จำกัดความถี่ ทำ pagination และเก็บผลค้นหาชั่วคราวตามข้อกำหนด API |
| ผู้ใช้กังวลเรื่องไมโครโฟน | ขอสิทธิ์เฉพาะตอนจำเป็น แสดงสถานะไมค์ และไม่เก็บเสียงโดยอัตโนมัติ |

## ขอบเขต MVP ที่แนะนำ

- สร้างห้องและแชร์รหัสให้ผู้เล่น
- ค้นหาเพลงจาก YouTube แล้วเพิ่มเข้าคิวได้
- โฮสต์จัดคิวและเริ่ม/ข้ามเพลงได้
- เล่นผ่าน YouTube Player เต็มจอและแสดงหน้าคะแนนเมื่อเพลงจบ
- คิดคะแนนจากไมค์ในเพลงที่มีข้อมูลอ้างอิง พร้อมคะแนนโหวตเป็นทางเลือก
- ทดสอบ Cast ตั้งแต่ต้น และส่งมอบ Cast สำหรับอุปกรณ์เป้าหมายเป็นเฟสสุดท้าย
