# ผลตรวจเฟส 0 — แอปร้องเพลงบนเว็บไซต์

**วันที่:** 27 ตุลาคม 2026  
**สถานะ:** ยังไม่ผ่านเกณฑ์เฟส 0 — การค้นหาผ่าน แต่ยังยืนยันการเล่น IFrame และ Cast บนอุปกรณ์จริงไม่ได้

## สภาพแวดล้อมที่ตรวจพบ

- ตอนเริ่มตรวจเฟส 0 พื้นที่มีเพียง `karaoke-web-app-plan.md`; เพิ่ม POC ใน `phase0-probe/` แล้ว (สถานะนี้เป็นบันทึก ณ เวลาตรวจ ไม่ใช่สภาพปัจจุบัน)
- ไม่พบตัวแปรสภาพแวดล้อมที่ชื่อเกี่ยวกับ YouTube, Google หรือ Cast
- แผนยังไม่ได้ระบุรุ่นมือถือ เบราว์เซอร์ และอุปกรณ์ Google Cast ที่จะใช้รับรอง
- มีสคริปต์ถาม API key แบบซ่อนและส่งให้เฉพาะเซิร์ฟเวอร์ในเครื่อง โดยตรวจสถานะได้โดยไม่เปิดเผยค่า

## ผลทดลองในเครื่อง

- ตรวจไวยากรณ์ Node.js ของเซิร์ฟเวอร์และ Python ของสคริปต์ Playwright ผ่าน
- Playwright/Chrome ยืนยัน health endpoint และกรณีไม่มี API key แสดงข้อผิดพลาดที่คาดไว้
- เมื่อตั้ง API key ให้เซิร์ฟเวอร์ในหน่วยความจำแล้ว การค้นหาแบบ `videoEmbeddable=true` และเพิ่มผลลงรายการทดลองผ่าน
- การค้นหาแบบ `videoEmbeddable=any` คืนผล 10 รายการและอ่านสถานะได้; รอบล่าสุดพบ 5 รายการที่ `status.embeddable=false` (จำนวนเปลี่ยนได้ตามผลค้นหา) และทั้ง 10 รายการมี `madeForKids=false`
- IFrame API ยังไม่ตอบสนองใน sandbox; หลังรอ 10 วินาที watchdog แสดงสถานะหมดเวลา การตรวจซ้ำจาก Node sandbox อีกตัวพบว่า DNS resolve ได้ แต่คำขอ HTTPS แบบ HEAD ไป `www.youtube.com/iframe_api` ก็หมดเวลาที่ 8 วินาที จึงยังยืนยันการเล่น/จบ/เต็มจอไม่ได้
- จับภาพผล Playwright ใน sandbox ไว้ที่ `phase0-probe/artifacts/phase0-probe-results.png`; ภาพแสดงรายการผลค้นหาและสถานะ IFrame หมดเวลา
- ยังไม่ทดสอบ Cast หรือไมโครโฟนกับอุปกรณ์จริง

## ผลตรวจจากเอกสารทางการ

### YouTube Data API

- ก่อนฝังวิดีโอจริง ระบบต้องตรวจ `Made for Kids` status และปรับการเก็บข้อมูล/การติดตามตามนโยบาย YouTube; POC อ่านสถานะนี้ไว้แสดงผลแล้ว
- ค้นหาเฉพาะวิดีโอที่ฝังได้ด้วย `type=video` และ `videoEmbeddable=true`
- `search.list` มีโควตาเริ่มต้น 100 คำขอต่อวัน โดยแต่ละหน้าเพิ่มใช้คำขออีกหนึ่งครั้ง ควรจำกัดความถี่และจำนวนหน้าผลลัพธ์
- ผลค้นหาว่าฝังได้ยังต้องตรวจผลตอนเล่น เพราะวิดีโออาจถูกลบ ตั้งเป็นส่วนตัว หรือปฏิเสธการฝังภายหลัง

### YouTube IFrame Player

- ใช้ `onStateChange` ตรวจสถานะจบ (`YT.PlayerState.ENDED`) และ `onError` แยกวิดีโอที่หายไปหรือฝังไม่ได้
- ขนาดต่ำสุดที่เอกสารกำหนดคือ 200×200 พิกเซล และแนะนำ 480×270 สำหรับวิดีโอ 16:9
- ต้องคงปุ่มและแบรนด์ของ YouTube ไว้ ไม่วางส่วน UI ทับตัวเล่น และไม่ตัด `HTTP Referer`; ให้ผู้ใช้กดเริ่มเองเมื่อเบราว์เซอร์ไม่อนุญาต autoplay
- ปุ่มข้ามเพลงของโฮสต์ต้องแยกจากเหตุการณ์เพลงจบตามธรรมชาติ เพราะการสั่งหยุดอาจทำให้ตัวเล่นเข้าสู่สถานะที่ดูคล้ายจบได้

### Google Cast

- Web Sender ต้องให้บริการผ่าน HTTPS และรองรับเบราว์เซอร์ Cast ที่กำหนด โดยเอกสารระบุว่า Cast ไม่รองรับ Chrome บน iOS
- อุปกรณ์ผู้ส่งและตัวรับต้องอยู่เครือข่ายเดียวกัน; ตัวรับแบบกำหนดหน้าจอเองต้องลงทะเบียนแอปและอุปกรณ์เพื่อทดสอบ
- เอกสาร Cast อธิบายการส่งคำสั่งจาก Sender ไปยัง Receiver ผ่าน Cast SDK แต่ยังไม่ยืนยันเส้นทางที่นำ playback จาก YouTube IFrame ไปเป็นเซสชัน Cast ของแอป พร้อมซิงก์คิวและสถานะได้ จึงต้องพิสูจน์กับอุปกรณ์เป้าหมายก่อนรับรองฟีเจอร์นี้

## รูปแบบข้อมูลเพลงสำหรับคะแนน — ข้อเสนอ

ใช้เวลาเป็นมิลลิวินาทีเทียบจากจุดเริ่มเพลง และเก็บโน้ตเป้าหมายเป็น MIDI เพื่อเทียบระดับเสียงกับจังหวะได้ ส่วนข้อมูลอ้างอิงควรมีแหล่งที่มาและเวอร์ชันชัดเจน

```json
{
  "schemaVersion": 1,
  "youtubeVideoId": "video-id",
  "durationMs": 180000,
  "referenceSource": "curated-reference-v1",
  "notes": [
    { "startMs": 1200, "endMs": 1800, "midiNote": 60, "beat": 0 }
  ]
}
```

ยังไม่มีเพลงจริงพร้อมข้อมูลโน้ตที่ยืนยันสิทธิ์และความถูกต้อง จึงยังไม่เลือกเพลงตัวอย่างสำหรับคะแนนตามแนวทางเดิม ต่อมาผู้ใช้ระบุว่าไม่ต้องใช้โน้ตเพลง จึงเปลี่ยนขอบเขตคะแนนเป็นค่าประมาณจากเสียงร้องและความนิ่งของ pitch; ข้อมูลโน้ตไม่ใช่เงื่อนไขของเฟส 4 แล้ว

## เบราว์เซอร์และอุปกรณ์เป้าหมาย — ข้อเสนอที่ยังไม่ทดสอบ

- ผู้ส่ง: Chrome บนเดสก์ท็อป และ Chrome บน Android
- ไม่รับรอง Chrome บน iOS สำหรับการส่ง Cast จากเว็บ
- ตัวรับ: Chromecast หรือทีวีที่รองรับ Google Cast โดยต้องระบุรุ่นที่จะทดสอบก่อนผ่านเฟส

รายการนี้มาจากเอกสารความเข้ากันได้ ไม่ใช่ผลทดสอบบนอุปกรณ์จริง

## ขอบเขต MVP — ข้อเสนอ

- เดินหน้าห้อง ค้นหา คิว และเล่นผ่าน YouTube Player ตามเฟส 1–3 หลังผ่านประตูเฟส 0
- ให้คะแนนประมาณการจากสัดส่วนเสียงร้องและความนิ่งของ pitch โดยไม่เทียบกับทำนองเพลง; เปิดโหวตผู้ฟังเมื่อข้อมูลไมค์ไม่พอ
- ยังไม่ระบุว่า Cast ซิงก์กับคิวของแอปได้ จนกว่าจะทดสอบเส้นทางจริงอย่างน้อยหนึ่งชุด

## รายการทดลองและสถานะ

| การทดลองตามแผน | สถานะ |
|---|---|
| ค้นหาด้วย YouTube Data API และเพิ่มผลลงรายการทดลอง | ผ่าน: ค้นหาแบบกรองและเพิ่มผลได้ |
| เล่น IFrame แบบเต็มจอและตรวจจับจบเพลง | UI พร้อม; IFrame API หมดเวลาหลัง 10 วินาทีใน sandbox จึงยังไม่ผ่านการทดลอง |
| ทดสอบวิดีโอที่ฝังได้และฝังไม่ได้ | พบ candidate ที่ API ระบุว่าฝังไม่ได้ 5 จาก 10 รายการในรอบล่าสุด; ยังทดสอบพฤติกรรมตัวเล่นจริงไม่ได้ |
| Cast จากอุปกรณ์เป้าหมายและตรวจภาพ/เสียง/สถานะ | รอระบุและเข้าถึงอุปกรณ์จริง |
| เลือกเพลงตัวอย่างพร้อมโน้ตและจังหวะอ้างอิง | รอข้อมูลเพลงที่ตรวจสิทธิ์และความถูกต้อง |
| ระบุเบราว์เซอร์และทีวีรุ่นแรก | มีข้อเสนอเบื้องต้น; รอยืนยันและทดสอบ |

**ผลการผ่านเฟส:** ยังไม่ผ่าน เพราะเกณฑ์ค้นหา/เลือกผลลัพธ์ เล่นจนจบ และ Cast อย่างน้อยหนึ่งเส้นทางยังไม่มีหลักฐานจากการทดสอบจริง

## ผลทดลองเพิ่มเติมและการทำต่อ

ผู้ใช้เพิ่ม API key ไว้ในไฟล์เฉพาะเครื่องและผมโหลดค่าเข้าเซิร์ฟเวอร์ชั่วคราวโดยไม่พิมพ์หรือส่งค่าออกไป ผลค้นหาและเพิ่มลงรายการทดลองผ่านทั้งแบบกรองเฉพาะวิดีโอฝังได้และแบบรวม; รอบล่าสุดแบบรวมพบ candidate ที่ Data API ระบุว่าฝังไม่ได้ 5 จาก 10 รายการ และทั้งหมดมี `madeForKids=false` (ผลค้นหาเปลี่ยนได้ในแต่ละรอบ)

ตัวเล่นยังทดสอบไม่ได้: Headless Chrome ใน sandbox แสดงสถานะหมดเวลาหลัง 10 วินาที และ Node sandbox อีกตัวก็หมดเวลาขณะขอ `www.youtube.com/iframe_api` หลัง 8 วินาที; DNS resolve ได้ แต่การเชื่อมต่อ HTTPS ไม่สำเร็จ จึงยังยืนยันไม่ได้ว่า API โหลดและเล่นจนจบ ส่วน Cast ต้องทดสอบจาก HTTPS origin กับอุปกรณ์รับจริง ไฟล์ key ถูกเพิ่มใน `.gitignore` แล้ว ภาพจับหน้าจออยู่ที่ `phase0-probe/artifacts/phase0-probe-results.png`

เมื่อต้องการรันทดลองซ้ำ ใช้ `phase0-probe/run-probe.ps1` ใน PowerShell; สคริปต์ถาม key แบบซ่อนและเปิดเซิร์ฟเวอร์ที่ `http://127.0.0.1:4173` โดยไม่บันทึก key ลงไฟล์หรือส่งเข้าเบราว์เซอร์

หลังบันทึกผลเฟส 0 ได้เริ่มทำแอปสำหรับเฟส 1–5 ใน `app/`; ยังไม่ได้ทดสอบตามที่ผู้ใช้ขอให้พักการทดสอบไว้ก่อน ดูสถานะได้ที่ `phase-1-status.md`, `phase-2-status.md`, `phase-3-status.md`, `phase-4-status.md` และ `phase-5-status.md`
